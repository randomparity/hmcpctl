# Bounded C01 partition-settings verification

This procedure requires an exclusive root-coordinated hardware window for the
candidate commit. Follow [live testing](../live-testing.md), including independent
before/after snapshots and recovery. Nothing here authorizes hardware access.

Use the deployed checkout's `git rev-parse HEAD` and imported package source path
to establish that the running build matches the reviewed candidate. Run `just setup`
on that checkout and confirm its declared Python/platform prerequisites before the
window. Keep credentials, selectors and raw results private. Use one owned session;
close it before another arm uses the target. No foreign HMC session is reused.

The opt-in `lpar-settings` group is subtask 47. It creates one run-unique
`hmcpctl-live-lpar-<8 hex>` partition on the selected system, with required ownership
stamping, explicit small shared resources and five initial False/0 settings. It
leaves the creation profile unapplied. Nine fixed settings writes round-trip
performance collection, priority 0/255, simplified restart and migration flags;
`time_ref` is only set False. Each update checks that the partition is still
inactive and carries this run's caller token. Direct core creation is recorded
as observed; only actual MCP configure/read dispatches can receive live evidence.

No activation, power-off, profile mutation, guest clock change, migration or
remote-restart action is dispatched. A running time-reference partition can govern
hypervisor/service-processor time, so True remains not-run unless separately
approved for system-wide impact. Flags/readback do not prove guest runtime or
migration/restart readiness. Firmware rejection remains failure/unevidenced.

Choose a fresh private output directory outside the checkout. Set
`WINDOW_PRIVATE` to it and configure the authorized system through the existing
`.env` workflow; `sys-R1` below is an anonymous placeholder. Require the reserved
scratch prefix to be absent before starting. Keep other system writes quiescent.

```sh
uv run --no-sync python scripts/live_test_preflight.py --group lpar-settings
uv run --no-sync python scripts/live_test_baseline.py capture \
  --system sys-R1 --output "$WINDOW_PRIVATE/before.json"
uv run --no-sync python scripts/live_test_runner.py --group lpar-settings \
  --results-file "$WINDOW_PRIVATE/results.json"
uv run --no-sync python scripts/live_test_recovery.py \
  --results "$WINDOW_PRIVATE/results.json"
uv run --no-sync python scripts/live_test_baseline.py capture \
  --system sys-R1 --output "$WINDOW_PRIVATE/after.json"
uv run --no-sync python scripts/live_test_baseline.py compare \
  "$WINDOW_PRIVATE/before.json" "$WINDOW_PRIVATE/after.json"
```

Run recovery and after-snapshot even when the arm fails. Its cleanup only deletes
a matching-token inactive fixture; active/unreadable/foreign state requires manual
recovery and never triggers a power action. Absence is independently read twice,
and the system's partition names/free resources are compared to the baseline.
Never retry an uncertain create/write automatically. Keep the slot held until
recovery and independent comparison pass or root accepts the exact residual.

Bound the window to one fixture, nine updates, no True time-reference, no guest
boot, and a 15-minute arm budget plus 5 minutes for recovery; interruption still
requires recovery. Transport calls retain configured finite timeouts. Root must
confirm those timeouts fit the concrete window before dispatch. Publish only a
commit-stamped matrix generated by `scripts/live_test_evidence.py`; do not paste
raw results. Until an actual matching-commit arm completes, new settings remain
unevidenced. Retain True time-reference, IBM i, explicit-keylock REST composition
and guest-runtime behavior as separate not-run arms unless actually exercised.
